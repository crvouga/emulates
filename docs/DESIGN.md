# Design

Emulators is a quiet, typographic site: paper, ink, and one action color. The identity is
the name, one sentence, and a simple mark. The site, this file, the GitHub README, llms.txt,
and every package published to npm use the same sentence and the same mark.

## The sentence

**High-fidelity, in-process emulators for APIs and databases.**

The name and the sentence live in `project.ts` at the repo root as `project.name` and
`project.description`. `sites/docs/src/lib/content.ts` exposes them as `IDENTITY` (`name`
and `tagline`). Change them in `project.ts`. `bun run readme:sync` and `bun run llms:sync`
rewrite the generated files. Do not paraphrase the sentence in a package README or on a page.

Call the packages emulators: high-fidelity, in-process, API or database emulators. Say
"mock" only to contrast a hand-written mock with an emulator.

## The mark

`sites/docs/public/identity/emulators.svg` is the mark: two overlapping rounded squares on a
dark tile, an original and its stand-in. That path is `MARK_REPO_PATH` in
`sites/docs/src/lib/content.ts`. The docs site serves the same file as the favicon
(`image/svg+xml`) and renders it in the header and footer through
`sites/docs/src/components/Mark.astro`. The README image is `IDENTITY.mark`, that file on
`main`. `bun run check:readme` fails when the file is missing from the repo.

Do not recolor the mark, redraw it, or replace it with an emoji.

On the docs site, `/identity` shows the mark, the lockup, and the live tokens. This file is
the rules. `/docs/design` renders this file.

## Color

| Token | Light | Role |
| --- | --- | --- |
| `--bg` | `#f3eee4` | Paper |
| `--fg` | `#1e2823` | Ink. Text, and the double rules |
| `--accent` | `#243f34` | Live oak. A filled action |
| `--clay` | `#8d4a32` | Labels, the tagline, the current page |
| `--sage` | `#7d8a80` | A strong border |
| `--highlight` | `#c6a15a` | One highlight, never a fill |

Dark theme inverts paper and ink. Oak becomes a pale green (`#d5e0cc`) so a filled
button still reads. Clay lightens to `#e2b094`. Error and HTTP-method colors stay semantic
and are not part of the identity.

The header theme control offers system, light, and dark. System is the default and follows
the operating system. An explicit choice is stored as `mb:theme`.

The README license shield uses oak (`243f34`).

## Type

Headings are a serif: Iowan Old Style, then Palatino, then Georgia. Interface text is Avenir
Next, then the system sans. Code is the system mono. No webfont is loaded. On the landing
page the name is the title and the sentence sits under it in the serif, in clay.

## Baseline

Every HTML surface starts from `packages/ui`. A full document includes `CSS_RESET`. A widget
mounted inside another page uses `scopeReset(root)`, which keeps the same baseline inside
that root. The surface's own type, color, and spacing come after the reset.

## Motifs

- **Double rules.** Two rules, a thicker one and a thinner one, with a gap (`.double-rule`).
  The footer is closed by a full-width pair. A prose heading carries a short pair. The
  header is a single rule.
- **Cards.** A rectangular paper frame, a 1px border, almost no corner radius, no lift on
  hover. The service and category cards are cards. Hover draws a clay bar on the leading
  edge.
- **Labels.** Clay is for labels: eyebrows, the current nav item, the tagline. It is not a
  second fill for buttons or page backgrounds.

Corners are `--radius` (3px) or `--radius-sm` (2px). A coverage meter may stay a thin bar.

The page scrollbar stays visible, so moving between a short page and a long one does not
shift the layout. Its track is the page background (`--bg`) and its thumb is sage.

## What to refuse

- Gradient text, purple, and glow.
- An emoji or a mascot in place of the mark.
- Traffic-light dots on a code window. A code sample shows a filename and a double rule.
- Pill buttons, pill badges, and pill filters.
- A different sentence on npm than on the site.

## Where each surface gets it

| Surface | What it must show |
| --- | --- |
| Docs site | Tokens in `sites/docs/src/styles/global.css`. The mark and live tokens at `/identity`. This file at `/docs/design`. |
| GitHub README | Generated by `scripts/readme.ts` from `IDENTITY` and this guide. The mark, the name, and the sentence are in the header. |
| `llms.txt` | Generated by `scripts/llms-txt.ts`. The opening blockquote starts with the sentence. |
| npm | Every public package README starts with `# <package>`, a blank line, then the `EPIGRAPH` from `content.ts`. `pack:check` fails when that line is missing or rewritten. The rest of the README stays the integration guide. |
| Package pages on the site | Render that same README, so the sentence appears there too. |

The sentence is the only marketing line a package README carries. Do not add a second banner,
a logo image, or a palette to a service README. Agents read those files to call the API.

## Adding a page

Use the tokens. Use `Mark` (`sites/docs/src/components/Mark.astro`) for the mark, not a new
drawing. Use `.eyebrow` for a small label. Use `.btn`, `.badge`, and `.prose`. If a new
component needs a radius, a color, or a shadow that is not a token, add the token and the
reason to this file in the same change.
